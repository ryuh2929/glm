# 발견한 오류 또는 개선사항

기존 분석 도구의 구현과 명세를 대조하여 발견한 문제 및 개선안을 정리한다. 각 항목은 [기존 분석 도구 카탈로그](./기존%20분석%20도구%20카탈로그.md)의 관련 도구와 연결된다. 아래 개선안은 권고이며, 수정이 완료되었다는 의미는 아니다.

**확인 수준**

- **실행 재현:** 작은 입력으로 현재 동작을 확인했다. 도구 전체의 정확성을 검증했다는 뜻은 아니다.
- **코드 확인:** 구현 또는 명세에서 해당 처리·불일치를 확인했다. 영향의 크기는 자료와 설정에 따라 달라진다.
- **추가 검증 필요:** 위험을 만드는 처리 경로는 확인했으나 실제 오류 발생 조건이나 수치적 영향을 더 검증해야 한다.
- **개선 제안:** 계산 오류로 단정할 수 없지만 해석·재현·관리를 위해 보완할 수 있다.

우선순위는 결과 왜곡·실행 중단 가능성이 큰 항목을 **높음**, 명세·진단·재현성 보완 항목을 **중간**으로 분류했다. 이는 수정 순서를 정하기 위한 판단이다.

## 2. 입력 처리와 통계 모형

<a id="f01"></a>

### F01. 범주형 결측값이 기준범주로 해석될 수 있음

**구현 위치:** [_design_matrix](../tool_sample/tool_sample.py#L2918)

**대상:** [로지스틱 회귀](./기존%20분석%20도구%20카탈로그.md#tool-logistic_regression), [GLM](./기존%20분석%20도구%20카탈로그.md#tool-glm_regression), 공통 인코딩을 사용하는 예측·인과추론 경로. **확인 수준: 실행 재현.**

- **문제:** `_design_matrix()`가 범주형에 `get_dummies(drop_first=True, dummy_na=False)`를 적용한다. 사전에 결측 행을 제거하지 않은 호출부에서는 결측값과 기준범주의 더미 벡터가 같아진다.
- **근거:** 입력 `['A', 'B', None]`에서 A와 None이 모두 `group=B: 0`으로 인코딩된다. 결과 행에는 NaN이 없어 인코딩 후 `dropna()`로도 제거되지 않는다.
- **영향:** 미기록 값을 실제 기준범주로 취급하여 회귀계수·예측·교란 조정에 영향을 줄 수 있다. “완전사례 분석” 또는 “불완전 행은 예측하지 않음”이라는 설명과도 어긋날 수 있다.
- **개선안:** 인코딩 전에 결측 정책을 적용한다. 행 삭제, 명시적 미상 범주, 적절한 대치 중 하나를 선택하고 제외수·처리 방법을 보고한다.

**적용 범위 주의:** 일부 Cox 경로는 인코딩 전에 결측을 처리하므로 모든 도구에 동일하게 발생한다고 단정하면 안 된다. 근거 함수: `tool_sample.py::_design_matrix` 및 각 호출부.

<a id="f02"></a>

### F02. 행 수 제한이 분석 대상 변경으로 보고되지 않음

**구현 위치:** [glm_regression](../tool_sample/tool_sample.py#L8267) · [_ml_fit_frame](../tool_sample/tool_sample.py#L8636)

**대상:** GLM·로지스틱·Cox·매칭·일부 예측/대치 경로. **확인 수준: 코드 확인.**

- **문제:** 여러 SQL에 `LIMIT _MODEL_MAX_ROWS`가 있고 상한은 1,000,000행이다. 일부 경로는 원래 조건을 만족하는 전체 행 수와 초과 여부를 확인하지 않는다.
- **근거:** `glm_regression()`, `logistic_regression()`, `_ml_fit_frame()`, `impute_missing()` 등의 자료 조회 코드.
- **영향:** 사용자가 지정한 코호트의 일부만 분석하면서 전체 코호트를 분석한 것으로 오해할 수 있다. 명시적인 무작위 표본추출도 아니며, 정렬이 보장되지 않은 LIMIT의 선택 행은 재현성 문제도 만든다.
- **개선안:** 상한보다 한 행 더 조회하거나 전체 건수를 확인하여 초과 시 명시적으로 중단한다. 표본추출을 지원한다면 방법·시드·원래 표본 수·선택 표본 수를 결과에 남긴다.

메모리 보호를 위한 제한 자체가 오류인 것은 아니다. **대상 자료가 바뀌었다는 사실을 알리지 않는 것**이 문제다.

<a id="f03"></a>

### F03. GLM 결과변수의 범위·형식 검증이 충분하지 않음

**구현 위치:** [glm_regression](../tool_sample/tool_sample.py#L8267)

**대상:** [GLM](./기존%20분석%20도구%20카탈로그.md#tool-glm_regression). **확인 수준: 코드 확인.**

- **문제:** Binomial에서 결과의 고유값 수는 확인하지만 허용 범위를 명시적으로 검사하지 않는다. Poisson·음이항에서는 음수 여부를 검사하나 count로 설명한 입력의 정수 여부는 확인하지 않는다.
- **근거:** `glm_regression()`의 `y.nunique()`, `y.min()` 검증 분기. `outcome_values`를 지정하지 않고 수치 결과를 바로 읽는 경로가 있다.
- **영향:** 이진 결과의 잘못된 코드나 count가 아닌 값이 들어와도 함수 단계에서 명확히 차단되지 않는다. 이후 라이브러리가 경고·실패하거나 사용자가 의도하지 않은 분석을 할 수 있다. 잘못된 입력이 항상 정상 결과를 반환한다고 확인한 것은 아니다.
- **개선안:** 개별 Bernoulli, 성공 수/시도 수, 비율 등 지원할 입력 방식을 먼저 정의하고 각각의 범위·형식·필요 가중치를 검사한다. count 모형도 실제 count 분석인지 준우도 목적의 비음수 연속값 분석인지 구별한다. 유한값 검사와 이해 가능한 오류 메시지를 추가한다.

<a id="f04"></a>

### F04. GLM의 완전분리 경고 처리 부족

**구현 위치:** [glm_regression](../tool_sample/tool_sample.py#L8267)

**대상:** [GLM](./기존%20분석%20도구%20카탈로그.md#tool-glm_regression)의 Binomial 경로. **확인 수준: 추가 검증 필요.**

- **문제:** 적합 예외와 `converged`는 확인하지만 완전분리 경고를 별도 판정하지 않는다.
- **근거:** `glm_regression()`의 `model.fit()` 및 결과 검사. statsmodels는 버전에 따라 완전분리를 예외가 아닌 경고로 보고한다.
- **영향:** 경고가 있어도 결과가 반환되는 경우에는 큰 계수와 신뢰하기 어려운 CI가 보고될 수 있다. 수렴 표시만으로 유한한 최우추정치의 존재가 보장되지는 않는다.
- **개선안:** 사용 라이브러리 버전을 고정하고 분리 경고, 비유한 계수·표준오차·CI, 수렴 상태를 함께 검사한다. 준완전분리와 희소 범주는 별도 진단 대상이다.

**검증 한계:** 이 항목은 기존 GLM의 모든 분리 사례를 실행한 결과가 아니다. 기존 함수의 전체 적합 경로와 설치 버전에서 추가 재현이 필요하다. 참고: [statsmodels GLM의 완전분리 경고 변경](https://www.statsmodels.org/v0.14.4/generated/statsmodels.genmod.generalized_linear_model.GLM.html).

<a id="f05"></a>

### F05. GLM 효과 척도와 절편의 표시가 모호함

**구현 위치:** [_glm_effect_label](../tool_sample/tool_sample.py#L3547)

**대상:** [GLM](./기존%20분석%20도구%20카탈로그.md#tool-glm_regression). **확인 수준: 코드 확인.**

- **문제:** `_glm_effect_label()`은 Poisson·음이항의 log 링크에 노출량 여부와 무관하게 `rate_ratio`를 붙인다. 절편에도 설명변수 계수와 같은 `estimate_type`을 사용한다.
- **영향:** 노출기간이 정의되지 않은 기대 count 비를 발생률비로 해석하거나, `exp(intercept)`를 집단 간 효과비로 오해할 수 있다. 동일 노출 조건에서는 비의 수치가 같을 수 있으므로 항상 계산 오류라는 뜻은 아니다.
- **개선안:** 결과변수의 정의와 노출량에 따라 count ratio와 incidence-rate ratio를 명시한다. 절편은 기준 평균·기준 오즈·기준 count 등으로 표시하고, 비교 효과 행과 구별한다.

<a id="f06"></a>

### F06. 가중치 종류에 따른 분산 추정 검토 필요

**구현 위치:** [glm_regression](../tool_sample/tool_sample.py#L8267)

**대상:** [GLM](./기존%20분석%20도구%20카탈로그.md#tool-glm_regression)의 가중 분석. **확인 수준: 추가 검증 필요.**

- **문제:** `weights_column`을 statsmodels의 `freq_weights`로 전달하며 기본 공분산 설정은 `nonrobust`다. 도구 설명은 IPTW 등으로 생성한 가중치도 이 입력에 사용할 수 있다고 안내한다.
- **근거:** `glm_regression()`의 `build_kwargs['freq_weights']` 및 `cov_type` 기본값.
- **영향:** 관측 반복 횟수인 빈도 가중치와 추정 성향점수 기반 가중치는 의미가 다르다. 선택한 추정량에 따라 모형 기반 분산이나 단순 HC0가 필요한 불확실성을 충분히 반영하지 못할 수 있다. 모든 가중 분석의 계수·SE가 틀렸다고 단정한 것은 아니다.
- **개선안:** 가중치 종류와 목표 추정량을 명세에 구분하고, 적절한 sandwich 분산 또는 성향점수 재적합을 포함한 bootstrap과 비교 검증한다. 가중치 범위·유효표본크기(ESS)·극단값 처리도 보고한다.

참고: [statsmodels GLM의 가중치 인수 정의](https://www.statsmodels.org/v0.14.4/generated/statsmodels.genmod.generalized_linear_model.GLM.html).

### F07. Table 1 기본값의 명세·구현 불일치

**구현 위치:** [table1](../tool_sample/tool_sample.py#L11112)

**대상:** [Table 1](./기존%20분석%20도구%20카탈로그.md#tool-table1). **확인 수준: 실행 재현.**

- **문제:** `tool_desc.py`는 `pval`, `smd`, `overall`의 기본값을 false라고 설명하지만 실제 `table1()` 인수의 기본값은 모두 True다.
- **근거:** 함수 시그니처와 `param_specs`를 비교하는 테스트로 확인했다. p값·SMD는 실제 실행에서 groupby가 있을 때만 활성화된다.
- **영향:** 설명만 읽고 생략한 옵션이 예상과 다르게 작동하여 표 구성이나 검정 여부가 달라진다.
- **개선안:** 의도한 기본값을 결정해 명세와 구현을 일치시킨다. 실제 함수 시그니처와 설명을 자동 대조하는 계약 검사를 두면 재발을 줄일 수 있다.

### F08. 미리보기의 잘림 표시가 부정확함

**구현 위치:** [_df_to_deliverable](../tool_sample/tool_sample.py#L2808)

**대상:** `_df_to_deliverable()`을 사용하는 결과 전달 경로. **확인 수준: 실행 재현.**

- **문제:** 미리보기는 `df.head(200)`이지만 `truncated`는 전체 건수와 `len(df)`를 비교한다.
- **재현:** 300행 DataFrame과 total=300을 전달하면 preview는 200행, row_count는 300, truncated는 False가 된다.
- **영향:** 실제 100행이 미리보기에서 빠졌는데 전체 결과로 오인할 수 있다. 원본 결과 관계의 행이 삭제된다는 뜻은 아니다.
- **개선안:** `total > len(preview)`를 기준으로 판정한다. 미리보기 크기와 전체 건수를 별도 필드로 명시한다.

### F10. mode 지정 시에도 수치형은 median으로 대치됨

**구현 위치:** [impute_missing](../tool_sample/tool_sample.py#L13396)

**대상:** [결측값 대치](./기존%20분석%20도구%20카탈로그.md#tool-impute_missing). **확인 수준: 실행 재현.**

- **재현:** 수치열 `[1, 1, 2, 3, 100, NaN]`에서 최빈값은 1, 중앙값은 2다. 실제 결측값은 2로 채워지고 보고된 방법은 mode다.
- **영향:** 요청한 처리 및 결과 설명과 실제 계산이 다르다. 동일한 명세로 분석을 재현하기 어렵다.
- **개선안:** 수치형 mode 분기를 구현하거나 옵션 이름·설명을 실제 동작에 맞춘다. 동점 최빈값의 선택 규칙도 정의한다.

**재현 범위:** 테스트에서는 저장소 의존성을 대체하여 대치 계산과 결과 등록만 확인했다. 실제 S3 저장 검증은 아니다.

### F11. MICE 대체 처리와 다중대치의 제한이 결과에 충분히 드러나지 않음

**구현 위치:** [impute_missing](../tool_sample/tool_sample.py#L13396)

**대상:** [결측값 대치](./기존%20분석%20도구%20카탈로그.md#tool-impute_missing). **확인 수준: 코드 확인.**

- **문제:** MICE에서 예외가 발생하면 로그에 남기고 중앙값 대치로 전환한다. 요약표에는 요청한 method가 남을 수 있다. 범주형은 모든 draw에서 최빈값으로 채운다.
- **근거:** `impute_missing()`의 `IterativeImputer` 예외 분기 및 범주형 `fillna(mode)` 처리.
- **영향:** 사용자는 실제 처리와 달리 MICE가 성공했다고 이해할 수 있다. 확정적 대치를 반복한 자료를 서로 다른 확률적 대치로 해석하면 불확실성이 과소평가될 수 있다. 범주형 최빈값 대치 자체가 언제나 오류인 것은 아니지만, 일반적인 범주형 다중대치와는 다르다.
- **개선안:** 요청 방법과 실제 방법을 구별하고 `fallback_reason`, 성공 여부, draw 수·변동성을 기록한다. 범주형 대치와 후속 pooling의 지원 범위를 명시한다.

**추가 주의:** 숫자 변환 성공 비율 80%로 수치형을 판정하여 결측이 많은 수치열이 범주형으로 처리될 수 있다. 변수의 의미에 따른 자료형 지정 기능이 필요하다.

가정 검정의 비유의는 비례위험 가정이 참이라는 증명이 아니다. 참고: [lifelines의 PH 가정 검토](https://lifelines.readthedocs.io/en/latest/jupyter_notebooks/Proportional%20hazard%20assumption.html).

### F13. 확률 보정 곡선의 명세와 bin 집계 보완 필요

- **개선안:** 하나의 bin 할당으로 표본 수·예측 평균·실제 발생률을 함께 계산한다. 빈 bin·동점 처리 규칙을 정의하고 설명을 실제 산출물에 맞춘다. bin별 CI는 별도 개선사항이다.

### F16. 생존분석의 시간단위와 관찰 범위 표시 부족

**구현 위치:** [kaplan_meier](../tool_sample/tool_sample.py#L5486) · [competing_risk_cif](../tool_sample/tool_sample.py#L5617)

**대상:** [Kaplan–Meier](./기존%20분석%20도구%20카탈로그.md#tool-kaplan_meier), [경쟁위험 누적발생률](./기존%20분석%20도구%20카탈로그.md#tool-competing_risk_cif). **확인 수준: 코드 확인.**

1. **시간단위:** KM은 입력 시간을 변환하지 않지만 결과 열 이름이 `time_months`다. 일 단위 자료를 넣으면 월 단위처럼 보일 수 있다. `time`과 단위 메타데이터를 구별하거나 입력을 월로 제한해야 한다.
2. **0사건 군:** CIF는 관심 사건이 0인 군을 skip한다. 해당 군의 위험이 0으로 관측되었다는 정보가 사라지거나 경쟁사건 정보도 빠질 수 있다. 0곡선·군별 사건 수·계산 불가 상태를 구분해 유지할 필요가 있다.
3. **관찰 범위:** CIF는 공통 grid로 맞추며 forward fill을 사용한다. 관찰 종료 이후 요청 시점의 값이 충분한 추적으로 추정된 값처럼 보일 수 있다. 군별 추적 범위·위험집단 수를 표시하고 지지구간 밖 값을 구별해야 한다.

이 항목은 KM이나 Aalen–Johansen 방법 자체의 오류가 아니라 입력·결과 표시와 후속 해석의 문제다.

- **근거:** `cox_time_varying()`의 `rows.append()`와 `tool_desc.py`의 Cox 계열 출력 스키마.
- **영향:** 명세를 따라 term/statistic 등을 읽는 후속 테이블·그림 작업이 실패하거나 잘못된 열을 찾을 수 있다.
- **개선안:** 이 함수의 실제 산출물에 맞춘 스키마를 정의하거나 모든 Cox 계열이 공통 스키마로 변환되도록 한다. 다중대치 결과도 별도로 계약 검사한다.

**관련 불일치:** 일반 Cox의 상호작용 행은 실제 `contrast`/`interaction_wald`인데 명세 일부는 `interaction_contrast`/`global_wald`를 사용한다. `cox_ph_univariate`의 실제 global_wald 행과 혼동하지 않도록 함수별로 맞춰야 한다.

## 6. 추가 확인된 결과 해석 문제

<a id="f20"></a>

### F20. E-value의 신뢰구간 귀무값 포함 판정 오류

**구현 위치:** [evalue](../tool_sample/tool_sample.py#L13005)

**대상:** [E-value](./기존%20분석%20도구%20카탈로그.md#tool-evalue). **확인 수준: 실행 재현.**

- **문제:** `evalue()`는 CI의 양 끝점 중 1에 가까운 하나를 고른 후, 점추정치와 반대 방향에 있는지로 귀무값 포함 여부를 판정한다. 신뢰구간 전체의 포함 여부를 직접 검사하지 않는다.
- **재현 입력:** `estimate=1.1`, `ci_lower=0.01`, `ci_upper=1.2`, `scale='rr'`.
- **기대 결과:** CI가 1을 포함하므로 `evalue_ci=1`.
- **실제 결과:** 상한 1.2를 가까운 끝점으로 선택하여 `evalue_ci=1.6899`를 반환한다.
- **영향:** 이미 귀무효과와 양립하는 구간을 두고, 이를 설명하려면 추가적인 교란 강도가 필요한 것처럼 표시한다.
- **개선안:** RR 척도로 변환한 하한·상한의 순서와 유효성을 검사하고, `lower <= 1 <= upper`이면 먼저 1을 반환한다. 그 외에만 귀무값에 가까운 한계값의 E-value를 계산한다.

**재현 범위:** 실제 `evalue()` 계산 메서드를 호출하되 자료 등록·파일 저장 함수를 메모리상의 결과 수집으로 대체했다. 저장소 동작은 검증하지 않았다.

<a id="f21"></a>

### F21. quasi-Poisson 별칭이 기대한 분산 보정을 보장하지 않음

**구현 위치:** [glm_regression](../tool_sample/tool_sample.py#L8267)

**대상:** [GLM](./기존%20분석%20도구%20카탈로그.md#tool-glm_regression). **확인 수준: 코드 확인.**

- **문제:** `_GLM_FAMILY_ALIASES`의 quasipoisson/quasi_poisson은 poisson으로 변환된다. 이 선택만으로 과산포에 맞는 scale 추정을 수행하는 분기는 없다.
- **영향:** 사용자가 quasi-Poisson을 지정했다고 생각해도 기본 설정에서는 일반 Poisson의 모형 기반 CI를 받는다. HC0 sandwich 분산 역시 quasi-Poisson의 공통 분산배율 추정과 항상 동일하지 않다.
- **개선안:** 동등하지 않은 별칭을 제거하거나 지원하는 평균·분산·공분산 추정 방법을 명시적으로 구현한다. 결과에는 입력한 별칭뿐 아니라 실제 family/link/scale/cov_type을 기록한다.

이 항목은 Poisson 평균 추정식 자체보다 **선택한 모형 이름과 불확실성 계산의 불일치**에 관한 문제다.

<a id="f22"></a>

### F22. PREDICT 계산 모듈과 임상 입력 계약의 확인 필요

**구현 위치:** [predict_breast_os](../tool_sample/tool_sample.py#L13547)

**대상:** [PREDICT Breast v2.1](./기존%20분석%20도구%20카탈로그.md#tool-predict_breast_os). **확인 수준: 코드 확인.**

- **실행 구성:** `predict_breast_os()`는 `tool.predict_breast` 또는 `predict_breast`를 import하지만 해당 계산 모듈이 현재 폴더에 없다. wrapper만으로 실제 수식·계수·범위 검증을 확인할 수 없다.
- **명세 불일치:** generation은 없음=0, 2세대=2, 3세대=3으로 안내하지만 같은 파라미터 설명에 상수 1을 지정하라는 문장이 있다. 이 코딩에서는 일관되지 않은 안내다.
- **해석 위험:** `predict_os_<year>y`는 수술 단독 기준 생존율이고 치료별 benefit은 순서가 있는 추가 이득이다. 이를 실제 치료 후 생존율이나 각 치료의 독립 효과로 읽으면 안 된다.
- **개선안:** 모델 계산 모듈·버전·출처·검증 예제를 함께 제공한다. 허용 코드와 단위를 단일 명세로 관리하고 잘못된 코드는 명시적으로 거절한다. 기준 생존율과 치료 적용 후 값은 별도 이름·단위로 제공하는 것을 검토한다.

외부 모델의 모든 수치가 틀렸다는 판단이 아니라, **현재 구성에서 실행·검증할 근거가 부족하고 입력 안내에 불일치가 있다**는 의미다.

<a id="f23"></a>

### F23. 성능표의 CI 제공 범위를 명확히 해야 함

**구현 위치:** [ml_classifier_performance](../tool_sample/tool_sample.py#L9693)

**대상:** [분류 성능 지표](./기존%20분석%20도구%20카탈로그.md#tool-ml_classifier_performance). **확인 수준: 코드 확인 / 개선 제안.**

- **현재 동작:** 표에는 모든 metric에 `ci_lower`, `ci_upper` 열이 있지만 bootstrap CI를 채우는 것은 ROC AUC다. Brier·민감도·특이도·PPV·NPV·보정 지표 등은 CI가 NULL이다.
- **영향:** 동일 스키마 때문에 모든 지표의 CI를 계산했다고 오해하거나, NULL을 계산 실패로 오해할 수 있다. AUC만 CI를 제공하는 설계 자체가 오류는 아니다.
- **개선안:** metric별 CI 지원 여부와 NULL 사유를 명시한다. 필요에 따라 적절한 지표별 CI를 추가하되, 고정 예측쌍 재표집과 전체 학습 절차 재표집의 차이를 보고한다.

**추가 명명 개선:** `pr_auc`는 `average_precision_score`로 계산된다. 곡선의 사다리꼴 면적과 구별하도록 Average Precision임을 명시하는 편이 정확하다.

<a id="f24"></a>

### F24. 결과 진단과 실행 상태의 구조화

**대상:** 여러 분석 도구의 공통 결과 관리. **확인 수준: 개선 제안.**

표본 수·제외 이유·수렴·가중치 진단 등이 일부 도구에서는 문자열 요약이나 로그에만 있고, 일부에서는 별도 표에 있다. 오류도 문자열·예외·결측 결과로 혼재한다. 결과를 다시 사용하거나 비교할 때 다음 항목을 구조화하면 좋다.

|관리 항목|권장 내용|
|---|---|
|실행 상태|success / partial / failed, 오류 코드와 사용자용 메시지|
|표본 흐름|필터 전후, 불러온 수, 결측 제외 수, 실제 분석 수·사건 수|
|자료 제한|행 수 상한, 표본추출 여부, 변수별 단위·코딩|
|모형 설정|실제 적용한 파라미터, 기준범주, 분포·링크, 가중치 의미|
|추론 진단|수렴·경고, CI 방법, 요청/성공 bootstrap 횟수, 대치 수|
|결과 전달|전체 결과 위치, preview 수, 잘림 여부, 주 출력과 부가 산출물 구분|
|재현 정보|코드·라이브러리·스키마 버전, 난수 시드|

모든 도구에 모든 필드를 강제하기보다는 적용되지 않는 필드는 명시적으로 구분한다. 정상 결과·계산 불가·미지원 기능을 같은 NULL로 표현하지 않는 것이 중요하다.

## 7. 확인 범위와 남은 검증

- 기존 동작을 확인하는 테스트 4개를 실행하여 범주형 결측 인코딩, 미리보기 잘림 표시, Table 1 기본값 불일치, mode 대치 불일치를 확인했다. 테스트 통과는 **현재 결함이 재현되었다는 뜻**이며 결함이 수정되었다는 뜻이 아니다.
- E-value는 위 입력으로 실제 계산 메서드의 결과를 추가 확인했다.
- 나머지 항목은 코드·명세 대조 또는 방법론적 검토다. 보정 bin 경계, 분리 상황, 가중분산 등은 별도 수치 검증이 필요하다.
- 모든 기존 도구·옵션 조합, 실제 연구자료, S3 저장, 포함되지 않은 임상모델 모듈을 실행 검증한 것은 아니다.
- 수정 후에는 문제별 경계 사례뿐 아니라 도구의 실제 출력 열·자료형·행 단위가 카탈로그와 일치하는지 함께 확인해야 한다.
